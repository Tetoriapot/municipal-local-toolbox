# 自治体ローカルツール箱

自治体・公共団体職員向けに、外部通信を行わない単一HTMLツールをTXT / HTMLで配布する静的サイトです。最優先仕様は [PROJECT_SPEC.md](PROJECT_SPEC.md)、進捗と残項目は [TASKS.md](TASKS.md) に記録しています。

## 現在の実装範囲

サイト本体と配布の仕組み、異動引継ぎノートv1.2.0、備品管理台帳v1.2.0の業務機能を実装しています。

- TOP、ツール一覧、8件の詳細、9カテゴリとカテゴリ一覧。
- 全角・半角を正規化する検索、カテゴリ複数選択、タグ絞り込み、おすすめ・新しい順・更新順・名前順。
- 検索条件のURL保存、再読込み、該当なし表示、条件のクリア。
- TXT優先のダウンロード、同じバイト列のHTML/TXT生成。
- ガイド、TXT変更方法、安全性、FAQ、更新履歴、利用規約、免責事項、サイト紹介、404。
- PC優先のレスポンシブUI、キーボード操作、フォーカス表示、読み上げ用ラベル、動きを抑える設定。

異動引継ぎノートでは、担当業務・年間予定・関係者・資料の保存場所・申し送り事項・チェックリストを登録、編集、削除できます。全文検索、確認済みの割合を示す完成度チェック、JSONバックアップ、印刷に対応しています。

備品管理台帳では、管理番号・備品名・カテゴリ・設置場所・購入日・状態・備考を登録、編集、削除できます。検索・絞り込み・並び替え、CSV出力、JSONバックアップ、印刷に対応しています。

他の6種類はv0.1.2-preview（配布確認版）です。共通のメモ、自動保存、保存エラー表示、JSONバックアップ書出し・読込み、印刷、削除確認を使えます。各ツール固有の業務機能は含まれません。配布確認版には実際の業務データを入力しないでください。

## 異動引継ぎノートの操作と保存

サイトと8ツールの右上に「更新情報」「ライトモード／ダークモード」「Help」を配置しています。配色は初回にOS設定を参照し、切替後はブラウザ内に選択を保存します。ツールの更新情報はファイル内の記録を表示し、外部から自動取得しません。

ブラウザ内の自動保存はJSONファイルの保存とは別です。作業後にJSONを書き出し、保存先でファイルを確認してください。「最終書出し操作」はボタン操作の日時で、ファイルの保存完了を保証する表示ではありません。PC・ブラウザ・ファイルの場所を変える前にJSONを書き出し、移行先で読み込んで内容を確認します。

実装済み2ツールでは、編集中の下書きをツールごとに1件保存します。「下書きを残して閉じる」で中断し、「下書きを再開」で続けられます。下書きがある場合は、新しい編集を始める前に再開するか削除してください。登録・保存するまで通常のJSON・CSV・印刷には含みません。下書きJSONは、移行先の同じツールの「データ管理」から「下書きを読み込む」で復元できます。通常のバックアップ読込みには使えません。既存の下書きがある場合は上書きせず、読込みを止めます。元の記録が変更・削除された下書きは、確認後に新規記録として再開します。

JSON読込みではツール・ファイル名・書出し日時・現在と読込み後の件数を確認できます。承認すると確定済みデータを置き換えます。下書きは別に残り、全削除後も「下書きを削除」で個別に削除します。

「サンプルで試す」は架空データを別画面で開きます。通常データと下書きは読み書きせず、変更は画面内だけに保持します。再読込みすると初期のサンプルに戻ります。サンプルの出力ファイル名には`sample-`が付きます。

1. 配布されたHTMLをブラウザで開きます。TXT版は拡張子を.htmlに変更して開きます。
2. ホームで自治体・部署名、前任者、後任者、引継ぎ日、メモを入力します。基本情報とメモは入力時に自動保存します。
3. 分類を選び「新規登録」を押します。記録は「登録する」「変更を保存」で確定します。編集中の未確定な内容はバックアップに含まれません。
4. 内容を確認した記録に「確認済み」を付けます。完成度は、6分類の全記録数に対する確認済み件数の割合です。必要な情報の充足度や正確さを自動判定する機能ではありません。
5. 作業後に「バックアップを書き出す」でJSONを保存します。復元時は全データを置き換えるため、必要な内容を先に書き出してください。

年間予定は4月から翌年3月の月別表示です。全文検索は6分類、基本情報、メモを対象にし、全角・半角と英字の大小を区別しません。スペースで区切った語をすべて含む記録を表示します。資料のパスやURLは文字として保存し、ファイルを添付したりリンク先へ接続したりしません。

「すべての記録を印刷」は全データを出力します。「表示中の一覧を印刷」は現在の分類の絞り込み結果、または全文検索の結果を出力します。ホーム・データ管理・ヘルプを表示中の場合は基本情報とメモを出力します。

保存先は利用中のブラウザのlocalStorageです。HTMLファイル自体には書き込みません。同じ保存場所で旧版のメモが見つかれば新しい保存領域に複製します。旧版の保存領域は変更しません。自動移行できない場合は、旧版でJSONを書き出して新しいツールへ読み込んでください。

同じツールを複数の画面で開き、保存内容の変更を検出した場合は上書きを止めます。未保存の内容をJSONへ書き出した後に「保存済みデータを読み直す」を使ってください。容量不足や保存制限がある場合も未保存と表示します。JSONは暗号化しません。

「データ管理」の全削除は「すべて削除」の入力が必要です。このバージョンのデータを空にし、旧版の保存領域と書き出したJSONは残します。データ形式と制限は[DATA_SCHEMA.md](DATA_SCHEMA.md)、検証内容は[TEST_CASES.md](TEST_CASES.md)に記載しています。

## 備品管理台帳の操作と保存

「備品を登録」で管理番号と備品名を入力し、必要な項目を記入して「登録する」を押します。状態は使用中・保管中・修理中・廃棄済み・未確認から選べます。廃棄済みに変更しても記録は残ります。管理番号は前後の空白、全角・半角、英字の大小を区別せず重複を確認します。

「備品一覧」では全項目をキーワード検索できます。カテゴリ、設置場所、状態で絞り込み、管理番号順・備品名順・購入日順に並び替えます。購入日が未入力の備品は購入日順の最後に表示します。一覧は50件ずつ表示します。

CSVと印刷は、全件または絞り込み結果を出力できます。絞り込み結果の出力には表示中のページ以外も含みます。全データ印刷にはメモも含めます。CSVは備品一覧の出力用で、メモ・復元用情報・不明な拡張項目は含みません。バックアップと復元にはJSONを使用してください。

CSVはUTF-8のBOM付きです。先頭の0を含む管理番号は、表計算ソフトの読込み時に文字列を指定してください。数式として解釈される可能性があるセルには先頭にアポストロフィを付けます。台帳とJSONの元データは変更しません。「CSVを読み込む」で取込み方法・文字コード・列の対応を指定し、検証とプレビューの後に追加・更新します。CSV内の管理番号重複・必須欄の欠落・不正な日付などがあれば全件の取込みを止めます。追加モードでは既存台帳との管理番号重複も拒否し、既存備品を保持します。更新モードの確認方法は下記「v1.2.0で追加した操作」に記載しています。どちらもメモと拡張項目は保持します。

メモは入力時、備品は登録・変更の確定時にブラウザ内へ保存します。旧版のメモが見つかれば新しい保存領域へ複製します。旧領域は変更しません。新しいファイル名で開く場合など、自動で見つからなければ旧版からJSONを書き出して読み込んでください。破損データ、保存禁止・容量不足、別タブでの変更を画面に表示します。

全削除には「すべて削除」の入力が必要です。JSON読込みは確認後に全データを置き換えます。現在のデータを保持したい場合は、先にJSONを書き出してください。

CSV読込みはUTF-8、BOM付きUTF-16の自動判定と、Shift_JIS・UTF-16LE/BEの手動指定に対応します。1行目を見出しとし、管理番号・備品名の列を指定してください。最大10MB・100列・3,000件で、追加後の台帳も3,000件以内です。購入日はYYYY-MM-DDまたはYYYY/M/D、状態は画面の日本語表示または保存用IDで読み込めます。このツールがCSV出力時に付ける数式対策のアポストロフィを戻す場合だけ、対応するチェックを入れます。

## v1.2.0で追加した操作

ツール一覧の「業務機能を実装済みのツールだけ」で対象を絞れます。検索・カテゴリ・タグと組み合わせることができ、URLと再読込みでも条件を保持します。

実装済み2ツールでは、直前の削除を「直前の操作を取り消す」で戻せます。備品CSVの追加・更新も取消対象です。取消用データは現在の画面内に1操作だけ保持し、別の変更・再読込み・画面を閉じる操作で失われます。他の画面で保存内容が変わった場合も取消を止めます。JSONバックアップの代わりにはなりません。全削除とJSON置換は取消対象ではありません。

「バックアップを読み込む」では、先に現在のデータを書き出すか、読込みファイルを選ぶかを選択できます。書出し操作だけで保存完了とは判断せず、保存先でJSONを確認してください。

下書きの移行は、元の環境で「下書きを書き出す」を実行し、移行先の「データ管理」から「下書きを読み込む」を選びます。同じツールの2MB以下の下書きJSONが対象です。既存の下書き・確定済みデータは上書きしません。未確定の必須欄が空でも移行でき、再開後の登録時に必須項目を確認します。

備品CSVの取込み方法は、従来の新規追加と、管理番号で照合する追加・更新から選べます。管理番号・備品名の列は必須です。更新では選ばない列を保持し、選んだ列の空欄は既存値を消します。追加・更新・変更なしと変更前後を20件ずつ確認できます。「変更前後と空欄による削除を確認しました」を選んだ後に反映します。CSVにない備品、メモ、ID、拡張項目は保持します。確認後に台帳が変わった場合は再検証が必要です。

備品には棚卸確認日・確認者・差異メモを記録できます。指定した暦年に確認済み・未確認の備品を絞り込み、CSV・印刷にも出力できます。過去の棚卸履歴や確認者本人の認証を行う機能ではありません。

引継ぎノートの編集画面には分類別の記入例があります。記入例を開いても入力内容は変わりません。申し送り事項とチェックリストは「期限が近い順」を選べ、期限未設定の記録は最後に表示します。既存の未確認フィルターと組み合わせられます。

ガイドの実画面は、ローカルpreviewの起動中に`node scripts/capture-guide.mjs`で更新できます。320 CSS pxの表示・キーボード・自動アクセシビリティ検査と、実ブラウザの拡大・スクリーンリーダー・実利用者による検証は区別して記録します。

## 起動・ビルド

公開先は[GitHub Pages](https://tetoriapot.github.io/municipal-local-toolbox/)、ソースは[GitHubリポジトリ](https://github.com/Tetoriapot/municipal-local-toolbox)で管理します。

`main`へpushすると、`.github/workflows/deploy-pages.yml`が型検査・単体テスト・ビルド・内部リンク検査を実行します。成功した`dist/`だけをGitHub Pagesへ配置します。Node.js 24とpnpm 11.25.0を使用し、Pagesの設定から`SITE_URL`と`BASE_PATH`を取得します。手動更新はGitHubのActionsにある「Deploy to GitHub Pages」から実行できます。手順は[GitHubの公式ドキュメント](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages)に沿っています。

GitHubにはアプリのソースと配布ファイルを保存します。利用者が入力した業務データはブラウザ内に保存され、公開時にアップロードされません。`.env`、ローカル検証結果、開発用の依存フォルダーもGit管理の対象から除外しています。

```sh
pnpm install --frozen-lockfile
pnpm tools:build
pnpm dev
```

開発用URLは `http://127.0.0.1:4321/` です。

```sh
pnpm check
pnpm test
pnpm build
pnpm verify
pnpm preview
```

`pnpm build` は配布ファイルを生成してからサイトを `dist/` に静的出力します。公開先には **distの内容** を配置してください。Nodeサーバーは公開先で不要です。配布サイトはHTTPで閲覧し、ダウンロードしたツールは `file://` から直接起動できます。

依存インストール済みでpnpmがPATHにない場合も、次のNodeコマンドで起動・ビルドできます。

```sh
node scripts/build-tools.mjs
node node_modules/astro/bin/astro.mjs dev --host 127.0.0.1
```

```sh
node scripts/build-tools.mjs
node node_modules/astro/bin/astro.mjs build
node node_modules/astro/bin/astro.mjs preview --host 127.0.0.1
```

この作業環境ではnpm/pnpmのコマンドがPATHにないため、同梱pnpmのCLIをNodeで実行して依存を導入しました。通常の開発環境では上記のpnpmコマンドを使用できます。

### サブディレクトリへの配置

GitHub Pagesなど、ルート以外に置く場合はビルド時に`BASE_PATH`を指定します。次はPowerShellの例です。

```powershell
$env:BASE_PATH = '/municipal-tools/'
$env:SITE_URL = 'https://example.jp'
pnpm build
pnpm verify
```

`SITE_URL` は実際の公開先に置き換えてください。未指定では推測したcanonical URLを出力しません。環境変数を解除するには `Remove-Item Env:BASE_PATH` / `Remove-Item Env:SITE_URL` を使用します。

## ツールデータ仕様と追加手順

`src/data/tools.ts` を単一のメタデータ定義として使用します。

| フィールド | 用途 |
| --- | --- |
| id | 小文字の英数字とハイフン。URL・配布ファイル名・保存キーで使用 |
| name / description / summary | 名称、カード用説明、詳細説明 |
| category | categories.tsのID |
| icon | Icon.astroに登録したSVGのキー |
| tags / features / useCases | 検索・絞り込み、機能、利用場面。previewの機能は予定として表示 |
| version | 配布物のバージョン |
| createdAt / updatedAt | YYYY-MM-DD。新着順・更新順の基準 |
| order | おすすめ順。アクセス数・利用数を装ったランキングではない |
| status | preview / ready。異動引継ぎノート・備品管理台帳はready、他の6件はpreview |
| implementation | readyツールの固有機能・保存方法・印刷・追加出力の説明 |
| downloads | TXT / HTMLのサイトルート相対パス |
| demo | 未公開はnull。実装済み2ツールはサンプルURL、他の6件はnull |
| network / account / externalLibrary | 現仕様ではfalse |

1. カテゴリが必要なら `src/data/categories.ts` に追加します。
2. `src/data/tools.ts` のdefinitionsに情報を追加します。
3. `Icon.astro` に既存のアイコンがなければインラインSVGのpathを追加します。
4. `pnpm tools:build` を実行すると、確認版のHTML / TXTが生成されます。
5. `pnpm build` で詳細・一覧・カテゴリへ反映します。
6. ツール数に依存するテストの期待値と、公開状況の文面を更新して検査します。

業務機能を追加する場合は、ツール専用ソースを`tools-src/{id}/`に用意します。現在の生成処理は`template.html`、`style.css`、`model.ts`、`runtime.ts`、`sample.json`を読み込みます。備品管理台帳では`csv.ts`と`csv-runtime.ts`、異動引継ぎノートでは`examples.ts`も使用します。実装・検証が済んだツールを`src/data/tools.ts`のreleasesに追加し、statusをreadyに変更してください。implementationにそのツールの操作・保存・出力の説明を登録します。実装済みツールの名称と配布確認版の件数はデータから生成します。

## 配布ファイルの生成

`scripts/build-tools.mjs`が、previewには`tools-src/shared/`、readyには`tools-src/{id}/`のソースを使用します。CSS・JavaScript・メタデータを埋め込み、UTF-8の単一HTMLを生成します。同じBufferを`.html`と`.txt`に書き込み、`manifest.json`にバイト数・SHA-256を記録します。TypeScriptは生成時にJavaScriptへ変換します。

生成済み配布物を直接編集せず、元ソースを変更して再生成してください。

readyツールでは共通の項目検証・DOM処理・保存処理を先に組み込みます。ソースのimportは1行で記述し、生成スクリプトの結合順に合わせてください。備品管理台帳のCSSは、引継ぎノートの共通画面構成を継承して一覧用のスタイルを追加しています。CSSの相対importは生成時に展開し、配布HTMLから外部CSSを読み込むことはありません。

- スクリプト・スタイル・SVGはファイル内部に含める。
- 外部API、CDN、Google Fonts、外部画像、外部JS/CSS、解析、広告、Firebase、Supabase、クラウドDB、AI APIは禁止。
- 外部接続を制限するCSPを設定する。
- 入力・読込みデータをHTMLとして評価しない。
- JSON読込みはスキーマ・ツールID・型・文字数・ファイル容量を検証し、置換前に確認する。
- データ破損時に既存保存領域を自動で上書きしない。
- localStorageの失敗を利用者に表示し、JSON書出しを可能にする。
